Process Flow: Login to Audit

How a request moves through the Vehicle Management Information System — from a badge-number login, through the role-gated modules where records get created and changed, down into the activity log that captures all of it, and back out through the one role allowed to review it.

user / system flow write → recorded to Activity Log read-only lookup, not logged retry / loop back

Role scope narrows automatically

The Dashboard and every module query is filtered by the signed-in role before it runs. A Unit Administrator sees their unit and every station beneath it; a Station Administrator sees only their own station. Nothing is hidden by the interface alone — the query itself never fetches out-of-scope rows.

The password gate can't be skipped

A session is created the moment credentials check out, but redirectAfterAuth() refuses to send that session anywhere except the forced password-change screen until is_password_changed flips to 1. The dashboard, and the "login" log entry itself, only exist on the other side of that gate.

Logging isn't a per-page decision

Every controller calls the same ActivityLog::record() helper on write, so there's no module where an edit can slip through unlogged. Uploaded files and passwords are stripped from the payload before it's ever written.
